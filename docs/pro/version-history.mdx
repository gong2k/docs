---
title: 版本历史与 schema 迁移
description: 记录、预览、恢复、比较、删除 drawDB Pro 云版本，并生成 up / down SQL 迁移脚本。
---

版本历史为云图表创建手动检查点。建议在大型 schema 改动、协作会话、或恢复操作之前使用。

## 打开版本历史

打开一张已保存的云图表，点击"分支/历史"图标。如果该图表还没上过云，先把它保存或移到云端。

历史按 20 条一拉加载。点 **Load more** 加载更早的检查点。

## 记录一个版本

1. 点 **Record version**。
2. 与最近一次的版本比对 JSON diff。
3. 选填一句不超过 200 字符的备注。
4. 点 **Create**。

drawDB 在创建检查点前会先 flush 掉待写的云端编辑。当 schema 没变化时，Create 会处于禁用状态；同样的快照不会被重复创建。

<Callout title="版本是手动的" type="info">
  当前的 Pro 行为不会自动创建检查点。需要在每个可恢复的里程碑点手动记录一条。
</Callout>

## 预览更早的版本

选中一条历史记录，或在其操作菜单里选 **Preview**。画布会切换成该版本的只读视图，并显示一个常驻的 **Back to current** 控件。

预览**不会**改动当前的云图表。再继续编辑前，请先点 **Back to current**。

## 恢复一个版本

具有编辑权限的用户可以选 **Restore this version**。恢复会把当前云图表替换成选中的快照。

<Callout title="先把当前状态保护起来" type="warn">
  在恢复之前请先把当前图表记录成一条手动版本。不要依赖"恢复"作为被覆盖状态的自动备份。
</Callout>

恢复后会重新加载完成，所选的 schema 就成为当前图表。

## 生成迁移

在某个版本的操作菜单里选 **Generate migration**。迁移生成目前处于 **Beta**。

比对结果包括：

- 只读 up SQL
- 只读 down SQL
- 一份 JSON schema diff
- 一份可下载的 ZIP，内含上述 SQL 文件

选中的版本会与历史面板里已经加载出来的**下一条更早**版本进行比对。要在分页边界附近生成迁移，请先点 **Load more** 以确保基线版本已经加载好。

Generic 图表可以显示 JSON diff，但生成 SQL 迁移脚本的能力不可用。SQL 生成只对受支持的具体数据库方言开放。

迁移比对**只关注 schema 结构**。画布上各元素的位置、缩放、标题、注释、主题区域等展示状态都不参与 SQL diff。

<Callout title="生成的 SQL 要复核" type="warn">
  迁移输出只是起点。在应用到真实数据库之前，请检查类型、约束、破坏性改动、数据回填与方言相关行为。
</Callout>

## 删除一个版本

图表创建者与团队 Admin 可以在版本的操作菜单里点 **Delete**。这条操作会永久删除该检查点。

其他具有只读权限的用户可以预览版本，但只有具有编辑权限的用户才能记录或恢复。
