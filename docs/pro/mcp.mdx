---
title: 用 MCP 把 drawDB 连接到 AI 工具
description: 配置只读 drawDB MCP 服务，让 Claude Desktop、Cursor、Cline、Goose、Windsurf 等兼容客户端可以读取云端 schema。
---

drawDB 的 Model Context Protocol (MCP) 服务为兼容的 AI 编程工具提供对 drawDB Pro 云工作区里数据库 schema 的**只读**访问。

它作为本地 Node.js 子进程运行，用你的 API Key 鉴权到 drawDB API，并暴露面向图表、表、列、关系、枚举、PostgreSQL 复合类型的精细工具。

<Callout title="设计上只读" type="info">
  MCP 不能创建、修改、导出、恢复或删除图表。也不暴露注释、主题区域、画布布局、SQL 导出和 DBML 导出。
</Callout>

## 准备事项

你需要：

- 一份启用了云存储、且至少有 1 张云端图表的 drawDB 套餐。
- 运行 MCP 客户端的机器上装好 Node.js 20 或更高版本。
- 能启动本地 `stdio` 服务的 MCP 客户端。
- 一个 drawDB API Key。参见 [创建与管理 API Key](/pro/api-keys)。

发布的 npm 包名是 `@drawdb/mcp`，默认连 `https://api.drawdb.app`。

## 配置 MCP 客户端

按下面的 JSON 配置加入一个本地 stdio 服务：

```json
{
  "mcpServers": {
    "drawdb": {
      "command": "npx",
      "args": ["-y", "@drawdb/mcp"],
      "env": {
        "DRAWDB_API_KEY": "ddb_your_key_here"
      }
    }
  }
}
```

把 `ddb_your_key_here` 替换成你创建 Key 时拿到的 token。把 Key 放在 drawdb 服务条目内的 `env` 字段里。

Claude Desktop、Cursor、Cline、Goose、Windsurf，以及其他会启动本地 MCP 进程的客户端都可以用相同的 command / args / 环境变量。具体在哪里加要看每个客户端的界面——找"添加本地 / stdio MCP 服务"的入口。

按客户端平时的 MCP 服务流程重启或重载，然后确认名为 `drawdb` 的服务及其工具都可用。

<Callout title="暂不支持纯 Web 端客户端" type="warn">
  当前包用本地 stdio transport。没法直连到只有 Web 的 ChatGPT 或 claude.ai 会话，因为 drawDB 还没提供这两类客户端需要的 HTTP + OAuth transport。
</Callout>

## 测试连接

在你的 MCP 客户端里发这条提示：

> 列出我的 drawDB 图表，然后把名为 "Orders" 的图表 schema 总结一下。

Agent 应该先调 `list_diagrams`，拿到图表 ID 后再针对该 ID 调用 schema 工具。

如果想绕过 MCP 客户端直接测 API，把 Key 放进环境变量并跑：

```bash
curl --fail-with-body \
  -H "X-API-Key: $DRAWDB_API_KEY" \
  https://api.drawdb.app/api/v1/diagrams
```

## 可用工具

| 工具 | 必填参数 | 返回内容 |
| --- | --- | --- |
| `list_diagrams` | 无 | Key 主人所属团队内的图表 ID、名字、数据库方言、更新时间 |
| `get_schema_summary` | `diagram_id` | 方言、统计与表名清单 |
| `list_tables` | `diagram_id` | 表名、注释、列数 |
| `describe_table` | `diagram_id`、`table_name` | 列、约束、默认值、注释、枚举值、索引 |
| `list_relationships` | `diagram_id` | 外键、基数、引用动作、复合列映射 |
| `describe_relationship` | `diagram_id`、`from_table`、`to_table` | 两个表之间指定方向的若干关系 |
| `list_enums` | `diagram_id` | 用户自定义的枚举名与取值 |
| `list_custom_types` | `diagram_id` | PostgreSQL 复合类型及其字段 |
| `search_tables` | `diagram_id`、`query` | 匹配的表或列名与注释 |

传给 `describe_table` 的表名大小写不敏感，但必须完全匹配表名。关系查询是**有方向的**：`from_table` 与 `to_table` 必须按 `list_relationships` 返回的方向填写。

`search_tables` 在一条查询匹配到多列或多注释时，可能返回同一个表的多次结果。

## API Key 能看到什么

MCP 进程是用创建它的用户的身份跑的，**不**限于编辑器里当前选中的工作区。

- `list_diagrams` 会扫描该用户所有团队内的云图表元数据。当前版本里，结果里可能包含一个 schema 读取后来被 "Invite only" 或 "No access" 拒绝的图表。
- 每次 schema 请求都会重新做访问检查。
- 显式撤销权限、退出团队、Key 过期或被删，都会阻止以后的访问。
- 仅本地的浏览器图表不会自动上传，也无法被 MCP 发现。

建议为每台设备 / 客户端单独创建 Key，这样吊销一个不会影响其他连接。

## 连接到自部署后端

`DRAWDB_BASE_URL` 是可选的。仅在你针对另一个 drawDB API 部署进行开发时设置：

```json
{
  "mcpServers": {
    "drawdb-local": {
      "command": "npx",
      "args": ["-y", "@drawdb/mcp"],
      "env": {
        "DRAWDB_API_KEY": "ddb_your_key_here",
        "DRAWDB_BASE_URL": "http://localhost:4000"
      }
    }
  }
}
```

## MCP 排错

| 症状 | 检查项 |
| --- | --- |
| `set DRAWDB_API_KEY env var before launching` | 客户端没把 Key 传进来。确认 `env` 在 drawdb 服务条目里。 |
| `npx` 或 Node 找不到 | 安装 Node.js 20+，并确保桌面客户端能通过其进程 `PATH` 找到。 |
| `401 missing api key` | `DRAWDB_API_KEY` 没进入进程。 |
| `401 invalid api key format` | Key 必须以 `ddb_` 开头；编辑器会话 token 不能用。 |
| `401 invalid or expired api key` | Key 过期、被删、被错误复制，或完整值丢失。创建替换 Key。 |
| `402 cloud_storage requires a Pro plan` | 账号已没有云存储权限。检查套餐或试用状态。 |
| 没有返回图表 | 确认图表已存到云，且 Key 主人仍属于它所在的工作区。 |
| `400 Invalid diagramId` | 先调 `list_diagrams`，用返回的 UUID 而非图表名。 |
| `403 not your diagram` | 摘要可以列出，但 Key 主人没有通过当前 schema 访问检查。 |
| `404 diagram not found` | 图表已被删，或 ID 错误。 |
| `Table not found` | 先调 `list_tables`，传入完整的表名。 |
| `No relationships from A to B` | 方向反了。改用 `list_relationships` 返回的方向。 |
| 最近改动未出现 | 等 drawDB 的云保存完成后，再次查询。 |

如果 Key 疑似泄露，请立即 [轮换它](/pro/api-keys#rotate-a-key)。
